# WeChat Mini Program Competitor Fieldwork Kit

这份文件用于补齐微信小程序同类竞品的真实体验证据。

当前状态：尚未完成真实微信内实测。下面是采集标准、样本框架和结论模板，不能把它当作已经完成的竞品结论。

不要把它当作已经完成的竞品结论；只有补齐微信内截图、录屏和样本记录后，才能升级为竞品实测结论。

目标不是证明某个竞品更强，而是回答 4 个产品问题：

- 中国大陆用户在微信里搜索健康记录、体重管理、喝水、睡眠时，实际看到什么产品
- 这些产品让用户先做什么：登录、授权、打卡、购买、看内容，还是填写记录
- 手动记录的摩擦有多大，哪些设计能降低每天记录成本
- 我们是否应该继续只保留睡眠 / 体重 / 饮水，还是先围绕体重管理增加上下文解释能力

本轮只做研究和路线判断，不直接新增健康指标、不接支付、不做设备接入、不做医疗建议。

## 1. 采集规则

每个样本至少采集 4 类证据：

| 证据 | 要求 |
|---|---|
| 搜索截图 | 微信搜索关键词、结果列表、产品名称、主体或服务类目可见时一起截 |
| 首开录屏 | 从点击进入到看到第一个核心动作，全程录屏 |
| 一次记录录屏 | 完成一次体重 / 饮水 / 睡眠 / 打卡 / 目标设置等核心动作 |
| 付费 / 提醒 / 分享截图 | 会员、报告、课程、硬件、订阅消息、分享海报、社群入口等任一出现就截 |

遇到手机号、身份证、支付、订阅消息、医疗授权、敏感健康授权时只截图，不继续授权或支付。

文件命名建议：

```text
research/evidence/YYYY-MM-DD/product-keyword/
├─ 01-search.png
├─ 02-first-open.mov
├─ 03-first-record.mov
├─ 04-retention-or-payment.png
└─ notes.md
```

## 2. 样本选择

至少完成 8 个样本，覆盖下面 8 类心智。真实产品以微信搜索结果为准，不强行凑固定名单。

### 样本 01：体重记录 / 体重日记

推荐搜索词：`体重记录`、`体重日记`、`体重管理`

要观察：

- 首次是否要求登录或授权
- 是否一屏完成称重记录
- 是否有目标体重、BMI、体脂、围度等表达
- 是否解释单日体重波动
- 是否引导看趋势、报告或挑战

### 样本 02：减肥打卡 / 轻体重管理

推荐搜索词：`减肥打卡`、`减脂打卡`、`轻体重管理`

要观察：

- 用户心智是记录工具、减肥计划、挑战，还是社群打卡
- 是否有连续打卡、日历、成就、分享海报
- 是否有明显焦虑或惩罚式语言
- 是否把饮食、运动、体重放在同一条路径里

### 样本 03：饮食 / 热量 / 轻断食

推荐搜索词：`热量查询`、`饮食记录`、`轻断食`

要观察：

- 是否用食物库、拍照、模板或快速选择降低输入成本
- 是否把体重变化和饮食解释关联起来
- 是否出现报告、会员、课程或 AI 建议
- 手动输入成本是否明显高于我们当前三项记录

### 样本 04：喝水提醒 / 饮水记录

推荐搜索词：`喝水提醒`、`饮水记录`、`喝水打卡`

要观察：

- 是否支持一键记录固定水量
- 是否有订阅消息、固定提醒时间、目标进度环
- 是否支持杯型、饮品类型、天气或运动场景
- 纯手动饮水记录是否有足够价值感

### 样本 05：睡眠记录 / 睡眠助手

推荐搜索词：`睡眠记录`、`睡眠助手`、`睡眠打卡`

要观察：

- 是手动记录、助眠内容、白噪音，还是设备/麦克风检测
- 是否要求敏感权限
- 是否让用户每天早上快速回填睡眠
- 睡眠是否作为健康记录主轴，还是作为辅助指标

### 样本 06：习惯打卡 / 日常记录

推荐搜索词：`习惯打卡`、`小日常`、`每日打卡`

要观察：

- 首次创建习惯是否比我们记录三项更快
- 连续记录反馈、日历、提醒、分享做得如何
- 是否有模板市场、会员皮肤、社群传播
- 哪些机制可以借鉴到健康记录，但不制造压力

### 样本 07：体脂秤 / 智能硬件健康

推荐搜索词：`体脂秤`、`智能体重秤`、`健康管理`

要观察：

- 是否依赖硬件自动同步
- 自动采集如何降低记录成本
- 免费价值和硬件/会员价值如何分层
- 我们短期无法接硬件时，应避免承诺什么

### 样本 08：综合健康 / AI 健康助手

推荐搜索词：`健康管理`、`AI 健康`、`健康助手`

要观察：

- 是否偏医疗服务、体检报告、问诊、用药或慢病管理
- 是否有明确免责声明
- 是否让用户输入更敏感的健康数据
- 哪些能力不适合当前 Personal Health Checker 阶段

## 4. 评分口径

每个样本按 1-5 分评分，分数不是排名，而是用于发现模式。

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 记录摩擦 | 很难找到记录入口 | 能完成但步骤多 | 30 秒内完成核心记录 |
| 微信原生感 | 像网页搬运 | 有基础小程序交互 | 明显适合微信内单手使用 |
| 回看价值 | 只保存数据 | 有趋势或摘要 | 能告诉用户下一步关注什么 |
| 留存机制 | 没有提醒或反馈 | 有打卡/日历 | 有温和且明确的回访理由 |
| 商业化清晰度 | 看不到付费理由 | 有会员/报告入口 | 权益、价格和场景都清楚 |
| 合规边界 | 难找协议 | 有基础协议 | 权限、隐私、非医疗边界清楚 |

## 5. 汇总结论模板

完成 8 个样本后，必须输出三类结论。

### 必须学

只收录对当前路线有直接帮助的内容，例如：

- 降低每日称重/记录摩擦的交互
- 保存后立即让用户知道下一步看什么
- 不制造压力的连续记录反馈
- 轻付费权益如何在不接支付前表达清楚

### 暂不学

默认先排除：

- 医疗诊断、问诊、用药、慢病管理
- 复杂 AI 健康建议
- 微信支付、会员订单、课程购买
- 社交排行榜和强竞争打卡
- 食物库、运动课程、设备同步的大系统

### 待验证

这些内容需要结合 alpha 用户反馈再决定：

- 睡眠和饮水是否是体重管理的有用辅助，还是输入负担
- 是否需要新增饮食/运动/围度等正式指标
- 用户是否愿意为 30 天体重观察报告付费
- 微信订阅消息是否值得进入下一阶段

## 6. 路线判断门槛

不要因为竞品有某个功能就直接做。只有满足下面条件，才考虑进入产品 backlog。

| 方向 | 进入条件 | 默认动作 |
|---|---|---|
| 新健康指标 | 至少 5/8 个样本证明它能解释体重变化，且 alpha 用户访谈中反复提到 | 先作为上下文标签或报告问题验证，不直接建正式指标 |
| 订阅消息 | 至少 4/8 个样本把提醒作为核心留存机制，且 alpha 次日回访低于 25% | 另开阶段评估，不在当前 alpha 直接做 |
| 付费权益 | 至少 3/8 个样本有清晰报告/会员权益，且我们 alpha 付费意愿 >= 5% | 先做样例报告和价格测试，不接正式支付 |
| 分享/社交 | 竞品有效但没有焦虑化表达，且用户主动要求分享记录 | 只考虑私密分享卡，不做排行榜 |
| 设备同步 | 硬件产品明显降低记录成本，但当前用户仍能手动坚持 7 天 | 只做远期记录，不进入当前小程序 alpha |
